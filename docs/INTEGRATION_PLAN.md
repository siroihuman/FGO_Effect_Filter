# FGO Effect Filter 統合計画

Author: argyi

## 目的

既存のスキル・宝具・クラススキル効果検索と、個別サーヴァントページから直接取得する特性検索を、最終的に1つのサーヴァント総合絞り込み機能へ統合する。

## 正本

- サーヴァント一覧: `/pages/54.html`
- 特性: 各サーヴァント個別ページの「特性」欄
- 効果: 各サーヴァント個別ページの保有スキル・宝具・クラススキル
- 「各特性持ち編集」ページ: 特性の有無を判定する正本には使用せず、表示順の参考にのみ使用

## 現在の統合構造

1. `Ra_FGOUnifiedFilter.js` が統合画面を起動
2. `Ra_FGOSharedFetch.js` が同一個別ページの取得を共有
3. 既存効果検索と `Ra_FGOTraitFilterCore.js` がデータを準備
4. `Ra_FGOUnifiedData.js` が両データをページID等で結合
5. `Ra_FGODataCore.js` が1騎1レコードの統合キャッシュを保存
6. `Ra_FGOCombinedSearch.js` が統合キャッシュを直接検索
7. `Ra_FGOTraitOrder.js` が既存特性ページを参考にした表示順を適用

## 統合レコード

```js
{
  id: "967",
  name: "ドロシー〔夏〕",
  className: "キャスター",
  rarity: 4,
  url: "https://w.atwiki.jp/siroi_human/pages/967.html",
  traits: [
    { name: "女性", raw: "女性", condition: "" }
  ],
  effects: { /* 既存効果検索の1騎分データ */ }
}
```

## 実装済み

- 特性検索基盤
- 特性表示順
- 共通データ取得基盤
- 統合bootstrap
- 統合データ読込
- 同一個別ページ取得共有
- 1騎1レコード統合キャッシュ
- 基本条件＋特性＋効果文言を同時指定する総合検索UI
- 総合UIへの特性表示順適用

## 次段階

総合検索UIの実機確認後、既存効果検索が持つ以下の条件を総合UIへ段階的に移植する。

- 効果候補の選択UI
- 効果ごとの倍率（以上 / 以下 / 一致）
- 対象（自身、味方単体、味方全体、敵単体、敵全体）
- 保有スキル / 宝具 / クラススキルの検索範囲
- 効果条件のAND / OR

その後、既存の効果検索画面・特性検索画面を開発用フォールバックへ縮小し、総合UIを正式画面とする。

## @wiki互換性・安全方針

- 実機確認が終わるまで既存検索本体は維持
- @wikiの `include_js` 制限に触れやすい処理は独立モジュール化
- 表示順と検索ロジックを分離
- 新規特性は表示順データに未登録でも検索対象から落とさない
- 統合キャッシュ生成に失敗しても既存2画面を利用できる状態を維持
- 各段階で@wiki実機確認後に次へ進む
