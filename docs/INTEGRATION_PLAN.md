# 効果検索・特性検索 統合計画

Author: argyi

## 目的

既存のスキル・宝具・クラススキル効果検索と、新規の特性検索を最終的に同一画面で併用できるようにする。

特性データの正本は各サーヴァント個別ページの「特性」欄とし、「各特性持ち編集」ページは表示順の参考にのみ使用する。

## 現在の構成

- `Ra_FGOEffectFilter.js`
  - 既存効果検索のbootstrap
  - v1.1.0圧縮本体を復元し、v1.1.1差分を起動時に適用
- `Ra_FGOTraitFilter.js`
  - 特性検索本体
  - @wiki上で正常表示確認済み
- `Ra_FGOTraitOrder.js`
  - 特性表示順だけを担当
  - @wiki上で正常表示確認済み
- `data/trait_display_order.txt`
  - 特性表示優先順
- `Ra_FGODataCore.js`
  - 統合用の共通データ取得基盤

## 共通化する処理

`Ra_FGODataCore.js` に以下を集約する。

1. `/pages/54.html` の取得
2. サーヴァント一覧表の解析
3. ページID・名前・クラス・レアリティ・URLの生成
4. 個別サーヴァントページ取得
5. 同時取得数の制御
6. localStorageキャッシュの共通操作

効果検索固有の「スキル・宝具・クラススキル解析」と、特性検索固有の「特性欄解析」は各モジュール側に残す。

## 統合後のサーヴァントデータ

```js
{
  id: '967',
  name: 'ドロシー〔夏〕',
  className: 'キャスター',
  rarity: 4,
  url: 'https://w.atwiki.jp/siroi_human/pages/967.html',
  traits: [],
  abilities: []
}
```

1騎につき1つの基本データを持ち、特性と能力データを同じサーヴァントへ紐付ける。

## 移行手順

### Phase 1: 共通取得基盤

- `Ra_FGODataCore.js` を追加
- 既存機能へ影響を与えない状態でAPIを確定

### Phase 2: 特性検索を共通基盤へ移行

- `Ra_FGOTraitFilter.js` の一覧取得・個別ページ取得を `RaFGODataCore` 利用へ変更
- 共通基盤がない場合の単独動作互換を当面維持
- @wiki実機確認

### Phase 3: 効果検索を共通基盤へ移行

- 圧縮前の効果検索本体を復元・管理可能なソースへ戻す
- 一覧取得・個別ページ取得を `RaFGODataCore` 利用へ変更
- 効果解析結果の形式は維持する
- 既存検索結果・倍率検索の回帰確認

### Phase 4: データキャッシュ統合

- 1回の個別ページ取得で特性解析と能力解析を両方実行
- 同じサーヴァントページを効果検索用・特性検索用に二重取得しない
- 24時間キャッシュも統合する

### Phase 5: UI統合

同一画面で以下を併用可能にする。

- サーヴァント名
- クラス
- レアリティ
- 特性
- スキル・宝具・クラススキル効果
- 効果倍率
- 効果対象
- 検索範囲
- AND / OR

特性条件と効果条件の間もANDで組み合わせられるようにする。

例:

- 女性
- 神性
- 味方全体の攻撃力アップ
- NP増加

をすべて満たすサーヴァントだけを表示できる。

## @wiki互換性

`include_js` の検査により、特性表示順を本体へ直接埋め込んだ版でエラーが発生した実績がある。

そのため今後も以下を守る。

- 検索本体への巨大な定数追加を避ける
- 表示専用データは外部テキストへ分離する
- 新規共通基盤は小さく保つ
- 既存正常版を残したまま段階移行する
- 各Phaseで@wiki実機確認後に次へ進む

## 正本

- サーヴァント一覧: `/pages/54.html`
- 特性: 各個別ページの「特性」欄
- スキル・宝具・クラススキル効果: 各個別ページの該当表
- 特性表示順: `data/trait_display_order.txt`
